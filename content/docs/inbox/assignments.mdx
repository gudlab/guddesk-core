title: Assignments & Workflows

GudDesk gives you a few simple tools to show who owns each conversation and what it is about.

## Manual Assignment

To assign a conversation:

1. Open the conversation from your inbox
2. Pick a team member in the **Assigned To** dropdown in the sidebar
3. Use the assignee filter at the top of the conversation list to see one person's conversations, or the unassigned ones

Assigning a conversation sends the `conversation.assigned` webhook event to any endpoint or agent that subscribes to it. GudDesk does not email or notify the assignee yet.

Assignment is manual today. Round-robin assignment and skill-based routing are planned (see the [roadmap](/roadmap)).

## Tags

Tags are free-form labels on a conversation:

- **Add a tag** from the conversation sidebar. Type a word such as "billing" or "bug" and press Enter
- **Remove a tag** from the same place
- Agents can also set tags through the REST API with `PATCH /api/v1/conversations/:id`

The inbox does not filter by tag yet.

## Snooze

Set a conversation's status to **Snoozed** from the sidebar to move it out of the Open tab. It stays in the Snoozed tab until someone changes the status, or until the customer replies in the widget, which reopens it.

The REST API accepts a `snoozedUntil` date, but GudDesk does not reopen conversations on a timer yet.

## Priority

Each conversation has a priority from 0 to 3, with 0 as the default. Set it through the REST API. SLA policies can target a specific priority, so higher-priority conversations can have tighter deadlines. The inbox does not show or edit priority yet.

## Automation Rules

You can create automation rules in **Automations**, with a trigger, conditions and one action. Rules run on their own when their trigger fires, so a rule can assign a new conversation, tag it, change its status or send a reply. Rules for conversations left unassigned are checked about every 5 minutes, counting from when the conversation was created or last unassigned. Conversations from before automation rules ran are skipped until they are assigned and unassigned again. For anything a rule can't do, [connect your own agent](/docs/agents/overview) and use the REST API.
