GudDesk is fully open source (AGPL-3.0) and designed to run on your own infrastructure. This guide covers deployment options for production environments.

## Install from Source

GudDesk runs from source on Node.js. There is no Docker image or Compose file. You need:

- Node.js 20.19 or later, and pnpm
- A PostgreSQL 15+ database that you run yourself or rent (for example Neon, Supabase or AWS RDS)

```bash
git clone https://github.com/gudlab/guddesk-core.git
cd guddesk-core
pnpm install

cp .env.example .env
# Edit .env with your production configuration (see Environment Variables below)

# Create the database tables
pnpm prisma db push

# Build for production (this also builds the chat widget)
pnpm build

# Start the production server
pnpm start
```

`pnpm install` also generates the Prisma client. The app listens on port 3000.

### Production Checklist

For production, we recommend:

- Use a managed PostgreSQL database with backups turned on
- Put GudDesk behind a reverse proxy with TLS (Nginx, Caddy, or Traefik)
- Set the four Pusher variables if you want live updates (see [Real-time updates](#real-time-updates-optional)). Without them the inbox and widget poll for new messages

## Process Manager

Use a process manager like PM2 for reliability:

```bash
pm2 start pnpm --name guddesk -- start
pm2 save
pm2 startup
```

## Reverse Proxy

### Nginx

```nginx
server {
    listen 443 ssl http2;
    server_name support.yourdomain.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### Caddy

```
support.yourdomain.com {
    reverse_proxy localhost:3000
}
```

Caddy automatically provisions TLS certificates via Let's Encrypt.

## Environment Variables

See the [Quickstart guide](/docs/quickstart) for the full list of environment variables. Key production variables:

| Variable | Description |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string |
| `AUTH_SECRET` | Session encryption secret (generate with `openssl rand -base64 32`) |
| `NEXT_PUBLIC_APP_URL` | Your public URL (e.g., `https://support.yourdomain.com`) |
| `RESEND_API_KEY` | Email delivery API key |
| `ANTHROPIC_API_KEY` | Required for AI agent features |
| `PUSHER_APP_ID` | Optional. Pusher app ID (server only) |
| `PUSHER_SECRET` | Optional. Pusher secret (server only, keep it private) |
| `NEXT_PUBLIC_PUSHER_KEY` | Optional. Pusher key, used by the dashboard and the widget |
| `NEXT_PUBLIC_PUSHER_CLUSTER` | Optional. Pusher cluster, for example `eu` or `us2` |

### Real-time updates (optional)

The four Pusher variables are optional. Set all four to get live updates over WebSockets. Without them GudDesk falls back to polling:

- The inbox refreshes the conversation list every 10 seconds and the open thread every 4 seconds, while the browser tab is visible.
- The chat widget checks for new messages every 4 seconds while it's open.

Typing indicators and collision warnings need Pusher, so they stay off in polling mode.

Next.js builds `NEXT_PUBLIC_` values into the browser code, so rebuild (`pnpm build`) and restart after you set or change `NEXT_PUBLIC_PUSHER_KEY` or `NEXT_PUBLIC_PUSHER_CLUSTER`. `PUSHER_APP_ID` and `PUSHER_SECRET` are read at runtime and only need a restart.

## Backups

You own the database, so you're responsible for backups:

```bash
# Manual backup
pg_dump $DATABASE_URL > backup-$(date +%Y%m%d).sql

# Restore from backup
psql $DATABASE_URL < backup-20250615.sql
```

Set up automated daily backups via cron or your cloud provider's managed backup service.

## Updating

```bash
git pull origin main
pnpm install
pnpm prisma db push
pnpm build
pm2 restart guddesk
```

Always review the [changelog](https://github.com/gudlab/guddesk-core/releases) before updating to check for breaking changes or required migration steps.
